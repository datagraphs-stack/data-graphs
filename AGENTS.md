# DataGraphs operating contract

DataGraphs is an **internet data foundry and graph intelligence platform**, not a CSV-analysis company. The first proving target is **one perfect 100-company Market Graph**. Studio is the preserved DataGraph Studio / Lab, demonstration and future bring-your-own-data interface; do not rebuild it as the company.

Before significant work read `docs/CONTINUITY.md`, `docs/FOUNDING_RECORD.md`, `docs/PRODUCT_VISION.md`, `docs/AUTONOMOUS_BUILD_DIRECTIVE.md`, `docs/ROADMAP.md`, `docs/PROJECT_STATE.md`, relevant accepted ADRs, architecture and actual Git/deployment state. The owner's complete September 9 commissions live in `docs/commission/`.

Operate **STATE → SELECT → BUILD → TEST → REVIEW → INTEGRATE → VERIFY → RECORD → CONTINUE**. Choose the next dependency-satisfied task that reduces distance to a commercially useful DataGraph. Ordinary reversible engineering and staging work are authorized, subject to existing controls. Fix test/build/schema failures without inventing Owner gates. Do not claim independent review when only self-review occurred. Never bypass branch protection or other required review.

Preserve **SOURCE → SNAPSHOT → OBSERVATION → CLAIM / FACT → ENTITY → RELATIONSHIP → GRAPH STATE → EVENT / SIGNAL → INTELLIGENCE PRODUCT**. AI proposes candidates; it is not evidence. Use deterministic logic where possible. Preserve ambiguity, contradictions, provenance, durable identity and reversible resolution. Missing evidence means no published assertion.

Run `npm test`, `npm run check`, and `npm run build`. Record exact execution/deployment evidence and update the concise live cursor in `docs/PROJECT_STATE.md`. Documentation, fixture tests and successful commits do not establish live capability.

Normal staging work may continue. Production deployment, DNS cutover, secret changes, paid commitments, customer-data mutation, destructive migrations, deleting evidence, irreversible identity merges and broad/uncontrolled acquisition require the applicable explicit authorization. No paid SaaS/data/AI dependencies are authorized; keep infrastructure Cloudflare-first and bounded. Never expose credentials or raw private data.

Continue within an active session until a genuine blocker, unsafe boundary or session limit. CI validates changes; it is not an always-on coding agent. Never claim unattended engineering, live crawling or deployment unless a real runner/runtime was installed and verified. Record exact blockers and independent work that remains possible; do not repeatedly retry unchanged failures.
